# 1.0.0 — Command factory hook

## What changed

`Strukt\Console\Runtime\Application` accepts an optional `$commandFactory`
callable as its third constructor argument. When provided, it is called with
the command class-string to build the command instance instead of the default
`new $class()`:

```php
$application = new Application(
    commandDirectory: $dir,
    docsDirectory: $docs,
    commandFactory: static fn (string $class): object => app($class),
);
```

When the factory is omitted (or not callable), commands are constructed with
`new` exactly as before. The built instance is still validated against
`CommandInterface`.

## Why

The framework `Shell` resolves commands through the `app()` container so
command constructors can receive dependencies. Building the instance inside the
console runtime keeps that decision out of the caller's dispatch loop while
preserving the previous behaviour for standalone use.

## Documentation

- None. `.md` command docs and the README examples are unchanged; the hook is
  optional and defaults to the existing behaviour.

## Tests

- None added for this hook. `tests/Unit/RendererTest.php` (added alongside the
  sectioned-list work) covers the renderer only; `Application` dispatch is
  exercised by the framework suite.

## Public API impact

- New optional constructor parameter:
  `Application::__construct(string $commandDirectory, ?string $docsDirectory = null, ?callable $commandFactory = null)`.
- Existing callers are unaffected.
